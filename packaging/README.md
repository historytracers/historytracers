# Packaging

This directory contains everything needed to package and distribute
History Tracers: Debian, RPM, Slackware, Windows (MSI via WiX), a
self-extracting static installer, the systemd service unit, the
configuration files and the Docker container definition.

All formats are generated by a single script from the repository root:
`historytracers2pkg.sh`.

## Requirements

The script compiles the whole project first (autotools, Go, Node), so a
full build toolchain is needed. To install the packaging/build
dependencies for your system:

```bash
sudo ./packaging/historytracers-install-requirements.sh
```

Refer to the root `README.md` for the complete build toolchain list.

## Generating the packages

Run the commands **from the repository root**. Every run first formats
and publishes the content (`autoreconf`, `./configure`, `make` and the
publisher), then produces the selected format into `artifacts/`.

| Option | Generates |
| --- | --- |
| `--deb`, `-d` | Debian packages |
| `--rpm`, `-r` | RPM packages |
| `--slackbuild`, `-s` | Slackware SlackBuild + tarballs |
| `--msi`, `-m` | Windows MSI (Windows/MSYS only) |
| `--static`, `-t` | Self-extracting installer + tar.gz |
| `--docker`, `-c` | Docker container image |
| `--validate`, `-v` | Runs `shellcheck` on the script itself |
| `--help`, `-h` | Help |

```bash
./historytracers2pkg.sh -d        # Debian
./historytracers2pkg.sh -r        # RPM
./historytracers2pkg.sh -s        # Slackware
./historytracers2pkg.sh -t        # Static installer
./historytracers2pkg.sh -c        # Docker container
./historytracers2pkg.sh -m        # MSI (Windows/MSYS only)
```

If no option is given, the format is auto-selected from the current
environment (Slackware, MSYS/Windows, Debian or Fedora/RHEL).

> Note: the content compilation step is long. All outputs land in the
> `artifacts/` directory of the repository root.

## Installing the packages

Examples below use version `1.0.0`; replace it with the produced version.

### Debian

```bash
sudo apt install ./artifacts/historytracers_1.0.0-*.deb
```

This installs the main package (`historytracers`: binary, systemd
service and configuration). The `-www` (web content), `-images`
(images) and `-devel` (sources) sub-packages produced by the same build
are used as dependencies; install them in the same command when their
repositories are absent:

```bash
sudo apt install \
    ./artifacts/historytracers_1.0.0-*.deb \
    ./artifacts/historytracers-www_*.deb \
    ./artifacts/historytracers-images_*.deb \
    ./artifacts/historytracers-devel_*.deb
```

Afterwards, enable the systemd service:

```bash
sudo systemctl enable --now historytracers
```

The service runs the History Tracers local server for the content
installed under `/var/www/htdocs/historytracers/` using the
configuration at `/etc/historytracers/historytracers.conf`. Check the
journal for details:

```bash
journalctl -u historytracers
```

### RPM

```bash
sudo dnf install ./artifacts/historytracers-1.0.0-*.rpm
```

Then enable the service the same way (`sudo systemctl enable --now
historytracers`).

### Slackware

```bash
# Extract the SlackBuild files, build and install
tar xzf artifacts/historytracers.tar.gz
cd historytracers
./historytracers.SlackBuild
sudo installpkg /tmp/historytracers-1.0.0-*.txz

# Note: the glob above also installs the -www package (web content for
# any web server). A separate images tarball is available at
# artifacts/historytracers-images-1.0.0.tar.gz if needed.
```

The `artifacts/historytracers-1.0.0.tar.xz` tarball holds the generic
source tree used by the SlackBuild.

### Windows (MSI)

Double-click `artifacts/HistoryTracers-1.0.0.msi` (or run
`msiexec /i HistoryTracers-1.0.0.msi`). Built only under Windows/MSYS
with the WiX Toolset.

### Static (self-extracting installer)

```bash
bash artifacts/historytracers-1.0.0-static-installer.sh          # install
sudo bash artifacts/historytracers-1.0.0-static-installer.sh     # system install
```

Useful options of the installer:

```bash
bash ... --check          # verify system dependencies
bash ... --list           # list the files it would install
sudo bash ... --prefix /usr/local
sudo bash ... --uninstall # remove the installation
```

A plain `artifacts/historytracers-static-1.0.0.tar.gz` tarball is also
generated for manual extraction, plus a
`artifacts/historytracers-www-1.0.0.tar.gz` web tarball for any external
web server (Apache, IIS, ...).

## Running the Docker container

```bash
./historytracers2pkg.sh --docker
```

This builds and tags `historytracers:<version>` (and
`historytracers:latest`), and exports a portable image tarball to
`artifacts/historytracers-<version>-docker.tar.gz`.

Run the container after the build:

```bash
docker run --rm -p 8080:80 historytracers:latest
```

Then open the site at <http://localhost:8080/>.

On another machine (or CI artifact distribution), load the exported
image first:

```bash
docker load < artifacts/historytracers-1.0.0-docker.tar.gz
docker run --rm -p 8080:80 historytracers:1.0.0
```

The image is self-contained: it ships the static web content (`www/`,
including `images/`) and an nginx webserver. It requires no
configuration to serve the default website. See `Docker/README.md` for
the container details.

## Troubleshooting

- `--docker` reports the CLI and daemon state separately: if the daemon
  socket is unreachable (for example a `permission denied`), it tells
  you to add the user to the docker group (`sudo usermod -aG docker
  $(whoami) && newgrp docker`) or to run the script with sudo.
- Missing tools for RPM/DEB builds: run
  `sudo ./packaging/historytracers-install-requirements.sh`.
- Script validation: `./historytracers2pkg.sh --validate`.
